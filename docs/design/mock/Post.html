EXP-006 2026-11-15 #senri#deno#bench

app.fetch を同期で返せば速くなるか

FAIL
対象
Senri(PR #134)
環境
EPYC 8 vCPU の VM
道具
wrk · Hono と交互

01目的

Senri の app.fetch は、すぐに答えられるときでも Promise を返しています。これをやめれば、Deno と Bun で速くなるかを確かめます。

02仮説

Hono をいつも Promise を返す形にすると、Deno で 6〜9%、Bun で 3〜4% 遅くなりました。なら、Senri から Promise を外せば同じくらい速くなるはずです。

03方法

ミドルウェアがなく、ハンドラーが同期のときだけ、Response をそのまま返すようにしました。

// before
if (res instanceof Promise) return res.catch(fail).then(end);
return Promise.resolve(end(res));

// after
return end(res);

main とこのブランチを、Hono と交互に 3 回ずつ測りました。

04結果

Hono に対して何倍か(中央値)
ランタイムシナリオmain変更後
Bunstatic0.9730.951
Bunparam0.9730.969
Denoparam0.7610.729

どれもブレの範囲で、速くなったとは言えませんでした。

05考察

main はもともと「解決済みの Promise」を返していただけで、Hono の async で包んだ形とは重さが違いました。仮説の土台にした数字が、比べる相手を間違えていました。

CONCLUSION / 結論

速さの得が見えないのに、型が変わる壊れる変更を払う価値はありません。この変更は入れないことにしました。
